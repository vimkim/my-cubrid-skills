## Testcase identity is per test, not one summary SHA

`summary.json.testcase_revision` comes from the first `/blob/<40hex>/` match in any test message. It neither verifies repository identity nor proves one shared suite revision. `sources/index.json` is stronger per-file evidence because records contain owner/repository, revision, path, source URL and download outcome. It still covers only links extracted from failure messages. Null summary revision and missing private sources occur in existing reports. [Revision extraction](/home/vimkim/gh/cubrid-circleci-analyzer/src/circleci.rs:111), [source extraction](/home/vimkim/gh/cubrid-circleci-analyzer/src/artifacts.rs:146), [observed limitation](/home/vimkim/gh/my-cubrid-docs/cbrd-27157/ci_analysis_report_d959074_codex.md:45).

Resolve `test_medium` and `test_sql` under `CUBRID_TESTCASES_DIR`; resolve `test_shell` under `CUBRID_TESTCASES_PRIVATE_EX_DIR` (user requirement). Require each configured directory to be a Git root; record remote identity, HEAD, branch and dirty state without exposing credential-bearing remote URLs. Resolve repository-relative full paths from evidence before basename search. Enumerate ambiguous matches and do not arbitrarily pick one. Verify the path exists at its proven testcase commit with Git tree/object inspection; compare local bytes and dirty state, not just HEAD. If exact commit differs, inspect Git objects or use an isolated worktree; never reset/switch the user's checkout. Record unresolved identity and resulting limit on conclusions.

The actual CircleCI configuration resolves public and private testcase repositories independently, preferring each repository's own `tc/pr-N` branch then `develop`. It exports the branch for entrypoint checkout. A resolver's earlier `TC_SHA` used for cache keys is not conclusive proof of the later checkout revision; branch races and fallback are possible. Capture checkout/entrypoint evidence or per-test immutable source references. Never infer one testcase commit from the engine SHA. ## Read-only fallback contract

1. Pin PR repository/number/full head SHA once and persist collection timestamp and collector/API versions. Recheck moving PR head before later mutation, without rewriting the original snapshot identity.
2. Prefer `cubrid-ci`; fallback is allowed when unavailable, unsupported, incomplete, or to collect extra GitHub checks. Record why. Do not bypass an integrity mismatch by treating suspect evidence as valid.
3. GET only: fetch full commit statuses, check runs, related Actions runs/jobs/logs, and CircleCI job/workflow/pipeline metadata plus tests/artifacts as needed. Follow GitHub Link pagination and CircleCI v2 `next_page_token`; record retrieval failure/truncation. For CircleCI job identity validate repository, full VCS revision, job name, build number and attempt. For newer APIs validate the equivalent pipeline/workflow relationship. Empty tests may mean missing results, not success; v2 documents a size-related empty-results limitation. [CircleCI API](https://circleci.com/docs/api/v2/index.html?section=reference), [pagination](https://circleci.com/docs/guides/toolkit/api-developers-guide/).
4. Use bounded retries/backoff for transient errors, respect service rate-limit guidance, and stop with access/coverage limitations after exhaustion. Never treat 401/403/404, missing private source permission, or absent logs as passing evidence. Do not repeatedly retry permanent failures.
5. Save raw responses and bounded relevant text logs/artifacts in a provenance-rich bundle; keep it distinguishable from collector schema output. No credentials/auth headers in reports. Do not publish signed artifact URLs. Do not POST reruns, comments, cancels or updates as part of collection.
6. Reconcile test counts, abnormal result counts, failure records and job-level failures. Preserve suite/job/attempt/node/test identity; same names on different nodes/attempts are not automatically one occurrence. Basename-only failed-tc lists are insufficient as the durable ledger.
