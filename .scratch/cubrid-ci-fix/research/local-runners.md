## Runner decisions supported by evidence

- Use `just ctp::shell-debug <test-directory>` (hyphen, not underscore). The recipe delegates to `cubrid-shell-debug.sh`; the directory should contain `cases/`. `shell-debug-many` uses the same helper. Root `just shell-debug` remains a compatibility wrapper. Sources: [ctp.just](/home/vimkim/my-cubrid/stow/cubrid/.just/ctp.just:5), [compat.just](/home/vimkim/my-cubrid/stow/cubrid/.just/compat.just:187).
- Prefer the existing helper over copying the old skill's recipes. It repairs missing shell FM configuration, disables testcase auto-update, removes the exclusion-file setting, allocates a PTY with `script`, preserves a transcript, and rejects NOK, zero execution, or missing summary. Its shell command interpolates an unquoted recipe argument and its `sed` substitution is not robust to special path characters; inspect paths and effective generated configuration. Sources: [helper](/home/vimkim/my-cubrid/bin/cubrid-shell-debug.sh:4), [configuration handling](/home/vimkim/my-cubrid/bin/cubrid-shell-debug.sh:24), [result handling](/home/vimkim/my-cubrid/bin/cubrid-shell-debug.sh:39).
- SQL and medium already support a single file: `ctp.sh sql -c <temporary-config>` or `ctp.sh medium -c <temporary-config>` with `scenario=<absolute-case-file>`. Both components call the SQL runner. That runner explicitly accepts files as well as directories, and Java discovery accepts matching individual files. Preserve suite-specific configuration and sibling fixtures/answers instead of copying only a SQL file. Sources: [component dispatch](/home/vimkim/CTP/common/src/com/navercorp/cubridqa/ctp/CTP.java:145), [runner validation](/home/vimkim/CTP/sql/bin/run.sh:152), [scenario argument](/home/vimkim/CTP/sql/bin/run.sh:765), [file discovery](/home/vimkim/CTP/sql/src/com/navercorp/cubridqa/cqt/model/Case.java:199).
- No noninteractive SQL/medium debug recipe was found in the current `my-cubrid` just modules. `justfile_ctp` contains only an interactive SQL launcher. A new framework is therefore not required for single-file capability, but a wrapper could improve ergonomics. This audit does not establish setup-elision correctness. Source: [interactive launcher](/home/vimkim/my-cubrid/justfile_ctp:1).
- Require the user's prerequisites before local execution: `git submodule update --init cubrid-jdbc`, then `just configure-build`. The latter exists; shared `prepare` initializes only CCI, so it does not replace the JDBC step. SQL setup compiles Java code against `$CUBRID/jdbc/cubrid_jdbc.jar`. Sources: [configure-build](/home/vimkim/my-cubrid/stow/cubrid/justfile:73), [prepare](/home/vimkim/my-cubrid/stow/cubrid/.just/core.just:5), [JDBC dependency](/home/vimkim/CTP/sql/bin/run.sh:575).
- `just build` compiles and installs; `just test` and `just build-test` run configured ctest tests only. They do not replace replaying the failed CTP case. Source: [build/test recipes](/home/vimkim/my-cubrid/stow/cubrid/.just/core.just:149).

## Roots, identity, and result evidence

- Honor `CUBRID_TESTCASES_DIR` for public SQL/medium and `CUBRID_TESTCASES_PRIVATE_EX_DIR` for shell. Both were unset in the audit shell; do not claim they are universally exported. Existing tooling recognizes these overrides. The public compatibility path `/home/vimkim/cubrid-testcases` resolves to `/home/vimkim/gh/tc/cubrid-testcases`; the private path `/home/vimkim/cubrid-testcases-private-ex` exists. Resolve configured roots to Git checkouts, inspect revision/status, and resolve CI-relative paths without guessing from basenames. Source: [override contract](/home/vimkim/my-cubrid/bin/cubrid-tc-sync.sh:26).
- Do not invoke `cubrid-tc-sync.sh` as a harmless discovery/preparation tool: its documented behavior includes fetching, branch switching, merging develop, and pushing both testcase repositories. Source: [sync usage](/home/vimkim/my-cubrid/bin/cubrid-tc-sync.sh:17).
- SQL/medium pass evidence is the actual case result plus `main.info` (`total`, `success`, `fail`), the printed result directory, and absence of core/setup errors. Require a positive matching execution count and all expected cases passing, not process exit zero. The runner prints Fail/Success/Total and does not explicitly exit nonzero just because `failNum > 0`. Source: [summary logic](/home/vimkim/CTP/sql/bin/run.sh:840).
- Shell pass evidence requires the expected case identity, positive execution count, zero failures, and complete final summary/transcript. The helper rejects several false-success states, but agents should still inspect the observed case set. Source: [helper result checks](/home/vimkim/my-cubrid/bin/cubrid-shell-debug.sh:44).
- SQL setup defaults `need_make_locale` to yes. Skipping locale/database setup is an optimization needing evidence that the reused environment matches the test; this audit did not validate it. Source: [locale default](/home/vimkim/CTP/sql/bin/run.sh:164), [locale step](/home/vimkim/CTP/sql/bin/run.sh:401).
